# Backend - Employee Salary Management System

## Prerequisites
- Java 1.8 (Zulu 8)
- Maven 3.6.3

## Setup & Run

```bash
cd backend
mvn clean install

mvn exec:java -Dexec.mainClass="com.salary.config.DataSeeder"   # seeds 10,000 employees -> salary_system.db

mvn spring-boot:run   # http://localhost:8080/api
```

## Testing

```bash
mvn test                              # all tests
mvn test -Dtest=EmployeeRepositoryTest
```

Repository tests run against an in-memory H2 database via `@DataJpaTest` — fast, deterministic, no file I/O. Production uses SQLite; the schema is equivalent since it's generated by the same JPA entities (test config disables `schema.sql`, which is SQLite-specific DDL, and lets Hibernate generate the schema instead — see `src/test/resources/application-test.properties`).

## Configuration

`src/main/resources/application.properties` controls the datasource, Hibernate dialect (`com.salary.config.SQLiteDialect`), and server port. Enable `spring.jpa.show-sql=true` for query debugging.

## Known gotchas

- Spring Boot auto-runs `schema.sql` against whatever datasource is active, including test databases. If you add new SQL-init-based tests, make sure `spring.sql.init.mode=never` is set for the test profile, or H2 will choke on SQLite-specific syntax like `AUTOINCREMENT`.
- No published Hibernate 5 dialect exists for SQLite — see `config/SQLiteDialect.java` for the minimal custom implementation this project uses.
